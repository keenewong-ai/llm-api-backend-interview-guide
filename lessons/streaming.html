L02 Streaming（SSE）

Streaming 令用戶好快見到第一個字（TTFT），但同時帶嚟斷線、buffering、backpressure 等一堆工程問題。

面試官真正想問嘅嘢 生產環境現實 解決思路 現實例子 + code

面試官真正想問嘅嘢

  • Streaming 係 LLM 產品體驗嘅核心，幾乎所有 chat 類產品都用
  • 考你 HTTP / network 基本功（chunked transfer、keep-alive、proxy 行為）
  • 考 error handling：已經送咗一半內容，之後出錯點算？
  • 考資源管理：斷線之後有冇 leak

🗣️ 示範答法（30 秒版）

「LLM streaming 一般用 SSE。Server 端我會將 upstream chunk 轉做 SSE event，每次 yield 前檢查 client 係咪已斷線，斷咗就 cancel upstream，慳 token。因為 header 已經送咗，中途錯誤要用 error event 通知前端。Client 端要自己 buffer，按 \n\n 拆 event，唔可以假設一個 chunk 一個 event。Deploy 時要關 proxy buffering、加 heartbeat、調高 read timeout。Monitoring 方面我會睇 TTFT、tokens/sec 同 stream 中斷率。」

生產環境現實

情境：本地開發 streaming 好正常，一 deploy 上 production（前面有 Nginx），用戶就見到「轉圈 10 秒然後一次過彈晒成段字」。另外 billing 發現有好多 token 係用戶早已離開頁面之後仲繼續 generate。

原因同修正：

  1. Nginx proxy_buffering 預設開 → 對 SSE route 關掉，或者 response 加 X-Accel-Buffering: no
  2. Backend 冇偵測 client disconnect → 每個 chunk 之前檢查連線，斷咗就 cancel upstream stream
  3. 加 heartbeat comment（: ping）防止 idle timeout 斷線

解決思路

大部分 LLM API 用 Server-Sent Events（SSE） 做 streaming：HTTP response 用 Content-Type: text/event-stream，每個 event 係 data: ...\n\n，逐 chunk（通常係 token 或幾個 token）推過嚟。

  • Chunk handling：一個 network chunk 唔等於一個 event，可能半個 JSON、可能幾個 event 黐埋，要自己 buffer 同按 \n\n 拆
  • Backpressure：如果 client 讀得慢，server 唔應該無限 buffer 喺 memory
  • Client disconnect：用戶熄 tab 之後，要 cancel upstream request，否則繼續燒 token
  • Proxy buffering：Nginx、部分 load balancer / CDN 預設會 buffer response，令 streaming 變成「最後一次過出晒」
  • Metrics：TTFT（time to first token）、tokens/sec、總時間、中途失敗率

⚠️ 常見陷阱

  • 假設一個 chunk = 一個完整 event，直接 JSON.parse → 偶發 parse error
  • 冇處理 client disconnect，用戶走咗仍然繼續 generate 同計錢
  • Stream 開始之後先出錯，但仍然想返 500 —— HTTP status 已經送咗，只能用 error event
  • 前面 proxy / CDN / compression middleware buffer 咗 response
  • Streaming 中途失敗由頭 retry，用戶見到重複文字；應該顯示部分結果 + 重試掣，或者 server 端記住已送內容
  • 冇記錄 TTFT，淨係睇總 latency，睇唔到真正用戶體驗

現實例子 + code

Python · FastAPI SSE proxy
# FastAPI SSE proxy：轉發 LLM stream 俾前端，處理 disconnect + 錯誤
import json
from fastapi import FastAPI, Request
from fastapi.responses import StreamingResponse
from openai import AsyncOpenAI

app = FastAPI()
client = AsyncOpenAI()

def sse(data: dict, event: str | None = None) -> str:
    prefix = f"event: {event}\n" if event else ""
    return f"{prefix}data: {json.dumps(data, ensure_ascii=False)}\n\n"

@app.post("/chat/stream")
async def chat_stream(request: Request):
    body = await request.json()

    async def gen():
        stream = await client.chat.completions.create(
            model=body.get("model", "gpt-4o-mini"),
            messages=body["messages"],
            stream=True,
        )
        try:
            async for chunk in stream:
                if await request.is_disconnected():
                    break                      # 用戶走咗，停止消耗 token
                if not chunk.choices:
                    continue
                delta = chunk.choices[0].delta.content
                if delta:
                    yield sse({"delta": delta})
            yield sse({"done": True}, event="done")
        except Exception as e:
            # 已經開始 stream，唔可以再改 HTTP status，只能送 error event
            yield sse({"message": "upstream_error", "detail": str(e)[:200]}, event="error")
        finally:
            await stream.close()               # 確保 upstream connection 釋放

    return StreamingResponse(gen(), media_type="text/event-stream", headers={
        "Cache-Control": "no-cache",
        "X-Accel-Buffering": "no",             # 叫 Nginx 唔好 buffer
    })
TypeScript · client-side SSE parser with abort
// Browser / Node 18+：用 fetch 讀 SSE（POST 唔可以用 EventSource，所以自己 parse）
export async function streamChat(messages: unknown[], onDelta: (t: string) => void,
                                 signal?: AbortSignal) {
  const res = await fetch("/chat/stream", {
    method: "POST",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify({ messages }),
    signal,                                   // 用戶按「停止」→ controller.abort()
  });
  if (!res.ok || !res.body) throw new Error(`HTTP ${res.status}`);

  const reader = res.body.getReader();
  const decoder = new TextDecoder();
  let buffer = "";

  while (true) {
    const { value, done } = await reader.read();
    if (done) break;
    buffer += decoder.decode(value, { stream: true });

    // 一個 network chunk 可能有半個或者幾個 event
    let idx: number;
    while ((idx = buffer.indexOf("\n\n")) !== -1) {
      const raw = buffer.slice(0, idx);
      buffer = buffer.slice(idx + 2);
      let event = "message";
      const dataLines: string[] = [];
      for (const line of raw.split("\n")) {
        if (line.startsWith("event:")) event = line.slice(6).trim();
        else if (line.startsWith("data:")) dataLines.push(line.slice(5).trim());
      }
      if (!dataLines.length) continue;        // heartbeat comment
      const data = JSON.parse(dataLines.join("\n"));
      if (event === "error") throw new Error(data.message);
      if (event === "done") return;
      onDelta(data.delta);
    }
  }
}
Nginx · SSE route config
location /chat/stream {
    proxy_pass http://backend;
    proxy_http_version 1.1;
    proxy_set_header Connection "";
    proxy_buffering off;          # SSE 必須
    proxy_cache off;
    proxy_read_timeout 300s;      # 長回答唔好被 idle timeout 斬
}
