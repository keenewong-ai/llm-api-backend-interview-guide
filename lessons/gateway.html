L07 LLM Gateway

當公司有多個團隊、多個 provider，就需要一個中央入口統一管理 auth、限流、成本同觀測。

面試官真正想問嘅嘢 生產環境現實 解決思路 現實例子 + code

面試官真正想問嘅嘢

  • 考 platform / system design 能力，常見於 senior 或 platform team 面試
  • 考你點樣平衡「集中管理」同「single point of failure / 額外延遲」
  • 考安全同合規意識（key 管理、PII、audit log）

🗣️ 示範答法（30 秒版）

「LLM Gateway 係所有 app 同 provider 之間嘅統一入口。App 用 virtual key，真正 provider key 只喺 gateway；gateway 做 auth、按 team 嘅 rate limit 同 budget、PII redaction、caching、routing 同 fallback，並為每個 request 記錄 team、model、tokens、latency 同 cost，用 OpenTelemetry 做 tracing。設計上 gateway 要 stateless、可以 horizontal scale，支援 streaming pass-through，避免成為瓶頸。可以用 LiteLLM 呢類 open-source proxy 起步，有特別需要再自建或擴展。」

生產環境現實

情境：公司有 5 個團隊各自直接 call provider，各自 hardcode API key。月尾 billing 大增但無人知係邊個團隊、邊個功能用咗；有團隊將含客戶電話號碼嘅資料直接送去外部 API。

處理：建立 gateway，所有團隊改用 gateway 嘅 virtual key；provider key 收返入 secret manager 並 rotate；每個 request 帶 team / feature metadata；按 team 設預算同 alert；敏感欄位送出前 redact；gateway 本身 stateless、多 instance、horizontal scale，避免 single point of failure。

解決思路

LLM Gateway 係介乎內部應用同 LLM provider 之間嘅 proxy 層，通常提供 OpenAI-compatible API，令應用唔使理底層用邊個 provider。

App A / App B / Batch jobs │ (internal API key / SSO) ▼ ┌──────────────── LLM Gateway ────────────────┐ │ Auth → Quota / Rate limit → PII redaction │ │ → Cache → Routing / Fallback → Provider call │ │ → Logging / Cost tracking / Tracing │ └──────────────────────────────────────────────┘ │ ▼ Provider A Provider B Self-hosted model

常見功能：

  • Central auth：內部 virtual key 對應團隊 / 項目，真正 provider key 只存喺 gateway（secret manager），唔會散落各個 app
  • Rate limit / budget：按 team / key 設 RPM、TPM、每月預算
  • Logging & cost tracking：每個 request 記錄 model、tokens、latency、cost、team
  • PII redaction：送出前遮蔽 email、電話、身份證號碼等（按合規要求）
  • Observability：metrics、tracing（例如 OpenTelemetry）、錯誤率、TTFT
  • Routing / fallback / caching：集中實現，唔使每個 app 自己寫

現成方案例如 open-source 嘅 LiteLLM（有 proxy server 模式）、Portkey 等 gateway 產品，亦可以自己用 FastAPI / Envoy 等自建。選擇時考慮：延遲 overhead、self-host vs SaaS（資料去向）、功能覆蓋、團隊維護能力。

⚠️ 常見陷阱

  • Gateway 變 single point of failure：要 stateless、多 instance、health check
  • Gateway 自己 buffer streaming response，破壞 SSE 體驗
  • Log 晒原文 prompt / response，變成新嘅資料洩漏風險
  • PII redaction 用簡單 regex 就當搞掂；高合規場景需要更完善嘅 DLP 方案同人工 review
  • 成本計算 hardcode 價錢冇更新
  • 加入太多同步處理步驟，令每個 request 多咗明顯延遲

現實例子 + code

Python · minimal gateway (auth, budget, redaction, cost log)
# 極簡 LLM Gateway（FastAPI）：auth → quota → PII redaction → forward → log cost
import re, time, logging, httpx
from fastapi import FastAPI, Request, HTTPException

app = FastAPI()
log = logging.getLogger("gateway")
upstream = httpx.AsyncClient(base_url="https://api.openai.com", timeout=60)

VIRTUAL_KEYS = {"vk_team_search": {"team": "search", "monthly_budget_usd": 500}}  # 實際放 DB
# 價錢只係 placeholder，以 provider 官方價錢為準
PRICE_PER_1M = {"gpt-4o-mini": {"input": 0.0, "output": 0.0}}

EMAIL = re.compile(r"[\w.+-]+@[\w-]+\.[\w.-]+")
PHONE = re.compile(r"\+?\d[\d\s-]{7,}\d")

def redact(text: str) -> str:
    return PHONE.sub("[PHONE]", EMAIL.sub("[EMAIL]", text))

def spent_this_month(team: str) -> float:
    return 0.0  # 實際由 DB / Redis 讀

@app.post("/v1/chat/completions")
async def chat(req: Request):
    key = req.headers.get("authorization", "").removeprefix("Bearer ").strip()
    tenant = VIRTUAL_KEYS.get(key)
    if not tenant:
        raise HTTPException(401, "invalid key")
    if spent_this_month(tenant["team"]) >= tenant["monthly_budget_usd"]:
        raise HTTPException(429, "team budget exceeded")

    body = await req.json()
    for m in body.get("messages", []):
        if isinstance(m.get("content"), str):
            m["content"] = redact(m["content"])

    t0 = time.perf_counter()
    resp = await upstream.post(
        "/v1/chat/completions", json=body,
        headers={"Authorization": f"Bearer {get_provider_key()}"},
    )
    latency_ms = (time.perf_counter() - t0) * 1000
    data = resp.json()

    usage = data.get("usage", {})
    price = PRICE_PER_1M.get(body.get("model"), {"input": 0, "output": 0})
    cost = (usage.get("prompt_tokens", 0) * price["input"]
            + usage.get("completion_tokens", 0) * price["output"]) / 1_000_000
    # 結構化 log：唔好 log 原文 prompt（或者要 redact + 有 retention policy）
    log.info("llm_request", extra={
        "team": tenant["team"], "model": body.get("model"), "status": resp.status_code,
        "latency_ms": round(latency_ms), "prompt_tokens": usage.get("prompt_tokens"),
        "completion_tokens": usage.get("completion_tokens"), "cost_usd": cost,
    })
    return data

def get_provider_key() -> str:
    import os
    return os.environ["OPENAI_API_KEY"]   # 實際用 secret manager
