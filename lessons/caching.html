L06 Caching

最平、最快嘅 LLM call 就係唔使 call。但 cache 錯咗嘅答案比慢更差。

面試官真正想問嘅嘢 生產環境現實 解決思路 現實例子 + code

面試官真正想問嘅嘢

  • LLM 成本高、延遲高，cache 係最直接嘅優化
  • 考你知唔知 LLM cache 同一般 HTTP cache 嘅分別（非確定性、語意相似）
  • 考 cache correctness：個人化內容、權限、stale data

🗣️ 示範答法（30 秒版）

「我會分三層：exact cache 用 model、messages、參數同 prompt version 做 hash key，只 cache temperature 0 嘅 request；semantic cache 只用喺低風險、非個人化嘅問題，threshold 用 eval set 調；同埋利用 provider 嘅 prompt caching，將固定 system prompt 同文件放前面。Cache key 一定包含 tenant 防止洩漏，配合 TTL 同版本號做 invalidation。指標方面睇 hit rate、慳咗幾多 token 同成本，同埋抽樣檢查 cached 答案嘅正確性。」

生產環境現實

情境：電商 FAQ bot 每日有大量重複問題，例如「幾時發貨」。加 exact cache 後成本明顯下降。之後團隊加 semantic cache，threshold 設太低，結果「點樣申請退款」同「點樣取消退款申請」返同一個答案，用戶投訴。

處理：semantic cache 只用喺非個人化、低風險嘅 FAQ 類問題；threshold 用 eval set 調；cache key 包含 tenant / language / prompt version；個人化或者有權限嘅內容唔 cache 或者按 user 分 namespace。

解決思路

  • Exact cache：用 (model, messages, temperature, tools, 其他參數) 做 hash 做 key；完全相同 request 直接返結果。適合 temperature=0、重複率高嘅 workload（例如 FAQ、batch 重跑）
  • Semantic cache：將問題 embedding，如果同之前問題相似度高過 threshold 就返 cached 答案。命中率高啲，但有答錯風險（「點樣取消訂單」vs「點樣唔取消訂單」可能好相似）
  • Prompt caching（provider 端）：部分 provider 支援對重複嘅 prompt prefix（例如長 system prompt、文件）做 cache，可以降低成本同延遲；有啲係自動，有啲要 explicit 標記，規則同價錢以官方文件為準。設計上要將固定內容放前面、變動內容放後面
  • TTL / invalidation：資料會變（RAG 文件更新、價格變動），cache 要有 TTL，或者 key 包含資料版本號
  • Embedding cache：同一段文字唔使重複 embed，ingestion 時好有用

⚠️ 常見陷阱

  • Cache key 漏咗參數（model、temperature、tools、prompt version），返錯答案
  • 跨 tenant / 跨 user 共用 cache，洩漏個人資料
  • Semantic cache threshold 冇用數據調，靠感覺
  • 冇 TTL 或 invalidation，資料更新後仍然返舊答案
  • System prompt 開頭放動態內容，令 provider prompt caching 失效
  • 淨係睇 hit rate，唔睇 cache 返錯答案嘅比率

現實例子 + code

Python · exact cache (Redis) + semantic cache sketch
import hashlib, json
import numpy as np
import redis

r = redis.Redis()
PROMPT_VERSION = "v3"     # 改 prompt 就改版本號 → 舊 cache 自然失效

def cache_key(tenant: str, model: str, messages: list, **params) -> str:
    payload = json.dumps(
        {"v": PROMPT_VERSION, "tenant": tenant, "model": model,
         "messages": messages, "params": params},
        sort_keys=True, ensure_ascii=False,
    )
    return "llm:exact:" + hashlib.sha256(payload.encode()).hexdigest()

def cached_completion(tenant, model, messages, llm_call, ttl=3600, **params):
    if params.get("temperature", 1) > 0:
        return llm_call(model, messages, **params)   # 高 temperature 唔 cache
    key = cache_key(tenant, model, messages, **params)
    if (hit := r.get(key)) is not None:
        return json.loads(hit)
    result = llm_call(model, messages, **params)
    r.set(key, json.dumps(result, ensure_ascii=False), ex=ttl)
    return result

# Semantic cache（示意）：實際應用 vector DB 做 ANN search
class SemanticCache:
    def __init__(self, embed_fn, threshold: float = 0.95):
        self.embed_fn, self.threshold = embed_fn, threshold
        self.vecs: list[np.ndarray] = []
        self.answers: list[str] = []

    def get(self, question: str) -> str | None:
        if not self.vecs:
            return None
        q = np.asarray(self.embed_fn(question))
        mat = np.stack(self.vecs)
        sims = mat @ q / (np.linalg.norm(mat, axis=1) * np.linalg.norm(q))
        best = int(np.argmax(sims))
        return self.answers[best] if sims[best] >= self.threshold else None

    def put(self, question: str, answer: str):
        self.vecs.append(np.asarray(self.embed_fn(question)))
        self.answers.append(answer)
